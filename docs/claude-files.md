# Claude Files transport

Common `/v1/files` image references supplied to Responses as `input_image.file_id` are uploaded after the Claude inference credential is selected. Claude uses `POST /v1/files` multipart uploads and Messages image blocks with `source.type: "file"` and the returned upstream `source.file_id`. Uploads and inference use the same selected credential and configured upstream base URL; API keys use Anthropic's key header on the official origin and OAuth credentials use Bearer authentication. The `files-api-2025-04-14` beta accompanies both requests.

Uploads and hosted-file inference reject redirects. Uploads reject oversized or invalid responses, and upstream authentication or capability errors. An upload failure stops inference rather than falling back to inline image data. Final payload rules may remove images, but cannot restore inline data or introduce unresolved or unauthorized file references. Proxy file IDs and uploaded bytes are retained in request-local preparation rather than an account-global upstream-ID cache, so another credential attempt uploads using its own account.

The shared local `/v1/files` endpoint accepts both OpenAI and Anthropic formats. Responses references require this native upload transport; ordinary Messages references use the portable image resolver. Deployments must follow Anthropic's applicable subscription and API terms, enable the Files capability for the selected credentials and upstream, and manage retention of uploaded upstream files. No alternate OAuth identity or multipart message signing is introduced.
